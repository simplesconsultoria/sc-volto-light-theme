# design-sync notes — sc-volto-light-theme

All converter prerequisites build and validate cleanly on `new-theme-system`: icon twins, synthetic `nm-overlay/`, standalone `dist/theme.css` + `dist/fonts/`, TypeScript `.d.ts` declarations (`index.d.ts`), and `dsEntry.ts` all prepare via `.design-sync/prepare.sh`, and **261/261 stories across all 50 `*.stories.*` files** render with zero runtime errors.

Target Claude Design project: `sc-volto-light-theme` (`f0a26637-18ca-4f24-80e7-8d196207efcc`, pinned in `config.json`).

## Pipeline summary (`.design-sync/prepare.sh`)

Volto is a webpack application, not a publishable component package, while the design-system converter bundles with standalone `esbuild`. Five mechanisms bridge that gap without forking the converter:

### 1. Synthetic `node_modules` (`build-overlay.py`)

`webpack-plugins/webpack-relative-resolver.js` rewrites `@plone/volto/X` to `@plone/volto/src/X` at build time (and similarly for every Volto addon). Standalone `esbuild` resolves plain node paths and fails without rewriting.

`.design-sync/nm-overlay/` solves this and three additional blockers:

1. **Package aliasing**: links `@plone/volto` (`core/packages/volto/src`), `@plone/volto-slate` (`core/packages/volto-slate/src`), `@kitconcept/volto-light-theme` (resolved at its installed version `8.1.4`), and all remaining declared addons in `package.json`. Sources are merged across `sc-vlt/node_modules`, `frontend/node_modules`, and `frontend/core/packages/volto/node_modules`.
2. **Addon mirroring & style stripping**: copies 534 addon/slate source files into the overlay with bare `import '...less'` / `import '...scss'` side-effect imports stripped (`STYLE_IMPORT_RE`), unblocking `QuoteBlock` (`@plone/volto-slate/blocks/Text`), `Accordion`, `Slider`, etc.
3. **Customization layering**: overlays `customizations/` in Volto precedence order (addons first, `sc-vlt` last — 47 files total, rewriting bridge relative imports to package-absolute paths) and patches 4 core `@plone/volto` modules whose `./` imports hit customized files (e.g. Teaser `View.jsx` -> `./Body`).
4. **Shared `@plone/registry` singleton**: shims `@plone/registry/index.js` on `globalThis.__dsPloneRegistry` and maps it through `.design-sync/tsconfig.ds.json` `paths` (which esbuild consults before local `node_modules`), unifying the bundle and story-preview config registries. That resolved `Grid`, `Highlight` (`UniversalLink` reading `config.settings`), and `Navigation`.
5. **Icon module substitution**: mounts `.design-sync/.cache/{volto,sc,vlt,sm}-icons` generated by `build-icons.py`.

### 2. SVG icon twins (`build-icons.py`)

Converter `esbuild` loads `.svg` as data URLs, whereas Volto's `Icon` component expects `{ attributes, content }`. `build-icons.py` generates `.svg.js` twins parsing SVG attrs/content identically to `svg-loader@0.0.2`:

- `.design-sync/.cache/volto-icons`: 335 modules
- `.design-sync/.cache/sc-icons`: 5 modules
- `.design-sync/.cache/vlt-icons`: 8 modules
- `.design-sync/.cache/sm-icons`: 25 modules

### 3. Curated component entry (`dsEntry.ts`) & `titleMap` (`config.json`)

`src/index.ts` exports only `applyConfig`. `src/storybook/dsEntry.ts` re-exports the 24 standalone shipped component views plus `DsPreviewProvider`, `StyledBlock`, `StylingMatrix`, and `MainImageBlockView` (loading `dsGlobals` and `dsConfig` first).

Because the repository grew to 50 story files (261 story exports), `.design-sync/config.json`:

- Disambiguates the 5 leaf collisions (`Blocks/EventMetadata/View` -> `EventMetadata`, `Blocks/Separator/View` -> `Separator`, `Blocks/Listing/Carousel` -> `CarouselTemplate`, `Blocks/Listing/Grid` -> `GridTemplate`, `Blocks/Listing/Highlight` -> `TeaserTemplate`).
- Excludes (`null`) 26 non-component stories: 5 theme control-panel stories (`ThemeForm`, `ThemeSwatches`, `ThemesList`, `ThemesToolbarActions`, `ThemesUI`), 1 widget (`SimpleColorPickerWidget`), 3 overview/page views (`Gallery`, `Inventory`, `DefaultView`), and 17 `RenderBlocks` styling showcase stories (`Blocks/Accordion`, `Blocks/Banner`, `Blocks/Carousel`, `Blocks/Event Calendar`, `Blocks/Grid`, `Blocks/Highlight`, `Blocks/Image`, `Blocks/Introduction`, `Blocks/Listing/Listing Block`, `Blocks/Logos`, `Blocks/Search`, `Blocks/Separator/In page`, `Blocks/Slider`, `Blocks/Table`, `Blocks/Teaser`, `Blocks/Table of Contents`, `Blocks/Video`).

### 4. Standalone `.d.ts` emission (`prepare.sh`)

The converter reads `<pkg>/index.d.ts` via realpath. `prepare.sh` cleans stale `*.d.ts` under `dist/` (preventing `TS5055`) and runs `tsc --emitDeclarationOnly --declaration --noEmit false --skipLibCheck --outDir ./dist -p tsconfig.json`, tolerating expected non-zero exit due to Volto webpack-alias `TS2307` while asserting `dist/src/storybook/dsEntry.d.ts` exists (283 `.d.ts` files emitted), then writes gitignored `index.d.ts`.

### 5. Compiled CSS & fonts (`build-css.sh`)

Compiles `vlt` + `sc-vlt` SCSS into `frontend/packages/volto-light-theme/dist/theme.css` (~3.35 MB) via `--load-path` + `.design-sync/.cache/scss-stubs` (stubbing `addonsThemeCustomizations*`, `volto-slate`, `volto-social-media` SCSS), rewrites `~...` webpack tilde imports, and copies 83 font and specimen files (9 `Inter-*.ttf` + 74 Metropolis files) solely from upstream `@kitconcept/volto-light-theme/src/theme/fonts` into `dist/fonts/`.

### 6. Runtime context (`dsGlobals.ts`, `dsConfig.ts`, `DsPreviewProvider.tsx`)

- `dsGlobals.ts`: defines `__CLIENT__`, `__SERVER__`, `__DEVELOPMENT__`, `__DEBUG__` on `globalThis`.
- `dsConfig.ts`: seeds Volto core settings, initializers (`Components`, `Widgets`, `Views`, `Blocks`, `slots`, `registerValidators`), `@plone/volto-slate`, all 16 declared addons, `applyConfig` from `sc-vlt`, plus `settings.loadables` / `lazyBundles` entries (`{ load: async () => null }`) so `injectLazyLibs` (e.g. `Search`) validates cleanly without pulling in `react-virtualized` or `prettier`.
- `DsPreviewProvider.tsx`: supplies `light` colour mode (`data-theme` + wrapper `colorScheme`), `default` block theme CSS custom properties, `--default-container-width`, `IntlProvider`, and `MemoryRouter`.

## Storybook build & verification

Reference Storybook build (run from `frontend/`):

```bash
cd frontend && VOLTOCONFIG=$(pwd)/volto.config.js \
  pnpm --filter @plone/volto build-storybook -c $(pwd)/.storybook \
  -o "$(git rev-parse --show-toplevel)/.design-sync/sb-reference"
```

When running the external converter, invoke from `frontend/core/packages/volto` so `index.json` `importPath`s resolve against `frontend/`.

## Re-sync notes

- **`config.json` absolute paths**: `storybookConfigDir`, `storybookStatic`, and `entry` hold machine-specific paths for running outside repo root; rewrite them for a new checkout before invoking the converter.
- **Gitignored outputs**: `.design-sync/nm-overlay/`, `.design-sync/.cache/`, `.design-sync/sb-reference/`, `frontend/packages/volto-light-theme/dist/`, and `frontend/packages/volto-light-theme/index.d.ts` must be regenerated via `./.design-sync/prepare.sh` after any fresh clone, `pnpm install`, SCSS change, icon addition, or customization edit.
- **Never sync into a project with manual edits**: converter reconciliation deletes untracked components in Claude Design.
